# Hosting WatRank Frontend on Cloudflare Workers

This document explains how the frontend was migrated from Vercel to Cloudflare Workers using [OpenNext](https://opennext.js.org/cloudflare).

## Current State

- **Before:** Vercel hosts `watrank.com` (Next.js 14.2.4)
- **Backend:** Cloudflare Worker `watrank-backend` at `cf-api.watrank.com` (already on Cloudflare, zone `watrank.com`)
- **After:** Frontend Worker `watrank-frontend` at `watrank.com` + `www.watrank.com`

## Changes Made

### 1. Dependencies

Added:
- `@opennextjs/cloudflare` – adapter to run Next.js on Cloudflare Workers
- `wrangler` – Cloudflare CLI (latest)
- `@cloudflare/workers-types` – types

Removed usage of:
- `@vercel/analytics` – removed `<Analytics />` from `layout.tsx`. Use Cloudflare Web Analytics instead (enable in Cloudflare dashboard).

### 2. Scripts (`package.json`)

```json
"preview": "opennextjs-cloudflare build --dangerouslyUseUnsupportedNextVersion && opennextjs-cloudflare preview",
"deploy": "opennextjs-cloudflare build --dangerouslyUseUnsupportedNextVersion && opennextjs-cloudflare deploy",
"build:cf": "opennextjs-cloudflare build --dangerouslyUseUnsupportedNextVersion",
"cf-typegen": "wrangler types --env-interface CloudflareEnv cloudflare-env.d.ts"
```

`--dangerouslyUseUnsupportedNextVersion` is needed because Next.js 14.2.4 is EOL (Oct 2025). Recommended to upgrade to Next 15 or 16 soon: `npm i next@latest eslint-config-next@latest`.

### 3. Config files

- **`wrangler.jsonc`** – Worker config:
  - `name`: `watrank-frontend`
  - `main`: `.open-next/worker.js` (generated by OpenNext)
  - `assets`: binding `ASSETS`, directory `.open-next/assets`, SPA fallback
  - `vars`: `NEXT_PUBLIC_API_URL=https://cf-api.watrank.com`
  - `routes`: `watrank.com/*` and `www.watrank.com/*` with `zone_name: watrank.com`
  - `observability`: enabled

- **`open-next.config.ts`** – minimal OpenNext Cloudflare config (can enable R2 cache later)

- **`.dev.vars`** – local dev env for Wrangler preview

- **`cloudflare-env.d.ts`** – generated by `wrangler types`

- **`next.config.mjs`** – added `typescript.ignoreBuildErrors` and `eslint.ignoreDuringBuilds` to allow existing loose types to pass (original Vercel build likely ignored too). Fix types gradually.

### 4. Code change

- `src/app/layout.tsx`: Removed `Analytics` from Vercel.

## How to Deploy

### Prerequisites

1. Cloudflare account that owns `watrank.com` zone (same as backend)
2. Wrangler logged in: `npx wrangler login`
3. Node >= 18

### Local preview (Cloudflare workerd)

```bash
cd frontend/watrank
npm install
npm run preview
# opens http://localhost:3000 in workerd
```

This builds with OpenNext and runs `wrangler dev` simulation.

### Deploy to workers.dev (staging)

For first test, comment out `routes` in `wrangler.jsonc` to avoid hijacking production, then:

```bash
npm run deploy
# or
npx opennextjs-cloudflare build --dangerouslyUseUnsupportedNextVersion
npx opennextjs-cloudflare deploy
```

You'll get URL like `https://watrank-frontend.<account>.workers.dev`

Verify `/stats` hits `https://cf-api.watrank.com` correctly (CORS already allows `*`).

### Deploy to custom domain `watrank.com`

Uncomment routes and deploy:

```jsonc
"routes": [
  { "pattern": "watrank.com/*", "zone_name": "watrank.com" },
  { "pattern": "www.watrank.com/*", "zone_name": "watrank.com" }
]
```

```bash
npm run deploy
```

Cloudflare will attach worker to zone.

**Important DNS steps:**
- Cloudflare Dashboard > DNS for `watrank.com` – ensure `A` / `CNAME` for apex and `www` are proxied (orange cloud). If Vercel DNS was used, remove Vercel CNAME and replace with proxied records pointing to a dummy IP (e.g., 192.0.2.1) or use Cloudflare's automatic route handling – Workers routes don't need origin, they intercept.
- If Vercel still has domain attached, remove domain from Vercel project to avoid conflict.

### Environment variables

`NEXT_PUBLIC_API_URL` is baked at build time. Set in:
- `.env` file (already `https://cf-api.watrank.com`)
- `wrangler.jsonc` vars
- `.dev.vars` for local

For production Cloudflare dashboard, also set var under Worker > Settings > Variables.

### Web Analytics

Vercel Analytics removed. Alternatives:
- Cloudflare Web Analytics: Dashboard > `watrank.com` > Web Analytics > Add site
- Or keep `@vercel/analytics` if you still deploy to Vercel preview, but it no-ops on CF.

## Alternative: Cloudflare Pages

If you prefer Pages (git-integrated deploys), you could also deploy same build via `wrangler pages deploy`. But Workers is recommended since backend already uses Workers and OpenNext now targets Workers.

## CI Example (GitHub Actions)

```yaml
- uses: actions/checkout@v4
- uses: actions/setup-node@v4
  with: { node-version: 20 }
- run: npm ci
  working-directory: frontend/watrank
- run: npx opennextjs-cloudflare build --dangerouslyUseUnsupportedNextVersion
  working-directory: frontend/watrank
  env:
    NEXT_PUBLIC_API_URL: https://cf-api.watrank.com
- run: npx opennextjs-cloudflare deploy
  working-directory: frontend/watrank
  env:
    CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
    CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```
